# Battalions in Space — large-scale team shooter (Unity 6)

Unity 6000.0.62f1 LTS · Built-in render pipeline · legacy Input Manager (+ gamepad axes) · Windows target (Android builds too) · MCP for Unity bridge.
All IP is original: four factions, their soldiers, heroes, ships, planets and the galaxy. Mechanics follow the 2005-era team shooters (command posts, tickets, heroes earned by points, class awards, space battles with boarding, a galactic campaign). Never use names, characters, designs or sounds from any existing franchise.

## Run
Open `Assets/Scenes/Main.unity` (empty) and press Play: `Game` boots itself (`[RuntimeInitializeOnLoadMethod]`) and builds everything in code — camera, sun, menus, battles. Nothing is authored in the scene and there are no art assets: models come from `MeshKit`, sounds/music from `Sfx`.
Source: https://github.com/darkmage1000/Battalions-in-space (public, branch `master`; builds, Library and preview PNGs are git-ignored, so the repo is code + settings only).
Menu **Battalions > Setup Project** (also runs on load), **Build Soldier Animator** (after changing the character FBX): scene + build settings, player settings, gamepad axes. **Battalions > Build Windows** → `Builds/Windows/BattalionsInSpace.exe`; **Build Android** → `Builds/Android/BattalionsInSpace.apk`.
Build self-test: `BattalionsInSpace.exe -autotest -screen-fullscreen 0` plays every map 12 s with the player spawned, opens a campaign, writes `%USERPROFILE%/AppData/LocalLow/Battalions Studio/Battalions in Space/autotest.txt` and quits.

## Testing in the editor (MCP)
The editor does not tick Play mode while it is in the background. Use `BIS.EditorTools.BattleTest` from `execute_code`: `Start(space, map, f0, f1)`, `Step(seconds)` (frames of 0.02 s via `EditorApplication.Step`, ~60 s of game per call max or the MCP call times out), `SpawnPlayer(cls, ship)`, `Place(pos, look)`, `Report()`, `Watch(seconds, reset)` + `WatchReport()` (per post: seconds being taken / contested / foes near; every change of hands; each squad's order and distance), `MapShot(map)` (Previews/Maps/<name>.png: minimap beside the bot walk grid), `PostEscape()`. The first call right after entering Play mode often does nothing — make a warm-up call. Screenshots: `manage_camera screenshot` with `output_folder: "Previews"` (git-ignored). Stop Play mode before recompiling.

## Architecture (Assets/Scripts, namespace BIS)
- **Core/** `Game` (bootstrap, menus backdrop, `StartBattle`), `Battle` (one battle: teams, `Participant`s, spawning, tickets + bleed, points, hero unlock, class awards, win rules, results; `Bonus` table for Conquest), `Ctl` (all input: keyboard/mouse + Xbox pad via `PadLX..PadDY` axes) + `Settings` (PlayerPrefs), `Mats` (materials from the three shaders in `Resources/Shaders`), `MeshKit` (flat-shaded vertex-colour shapes; colour alpha 0 = glows), `Sfx` (synthesised SFX + march music, pooled 3D sources), `Fx` (two particle systems fed with Emit), `AutoTest`.
- **Data/** `Defs` (WeaponDef / ClassDef / HeroDef / VehicleDef / FactionDef), `Factions` (the four factions + weapon templates `W`), `Maps` (7 land maps with post layouts and `MapFeature` layouts, the battle royale map `Maps.Royale`, 3 space maps, themes).
- **Royale/** `Royale` (battle royale rules: drop, zone, loot, chests, vaults, boss, placements), `Loot` (LootItem / LootChest, `Tiers`, `LootTable`, `LootModels`).
- **World/** `LandWorld` (height-field terrain in 64 mesh-collider chunks, themed props with primitive colliders, outposts, posts + vehicle pads, sky/fog, minimap texture) + `LandWorld.Layout` (the designed features: ridges, roads, rivers / lava / gulches, bridges, lakes, craters, fords, forests, towns, boulder fields), `CommandPost` (neutralise → capture, vehicle pads and respawn; `SpawnableFor(team)` = owned and no enemy standing in it).
- **Units/** `Unit` (soldier/hero: CharacterController movement, heat/ammo weapons, equipment, specials, hero abilities, death), `SoldierRig` (part model per body style + procedural animation), `Combat` (layers, `IDamageable`, `Participant`, `Shots` = every projectile drawn with `Graphics.DrawMesh`), `Gear` (mines, detpacks, supply crates, pickups), `PlayerControl` (input → unit/vehicle, cameras, spawn/dead/pause flow).
- **Vehicles/** `Vehicle` (ground hover vehicles, gunships, starfighters; seats: driver / gunner / passengers; lock-on, repair pulse, landing), `VehicleModels` (per-faction code-built models).
- **Space/** `CapitalShip` (box-built hull with a real hangar + interior corridors, `Subsystem`s: shield, 2 engines, 7 turrets, hangar control, life support, reactor; hull falls mostly through systems), `SpaceWorld` (two ships 1300 m apart, sky, planet / nebula / asteroids).
- **AI/** `BotBrain` (land infantry, drivers, gunners, gunship pilots, space jobs Dogfight / Bomb / Board / Escort / Defend / Sabotage, ship interior nav graph), `Commander` (squads and their orders), `Nav` (land walk grid + A* for infantry and ground vehicles; bots move through `BotBrain.Toward`).
- **Conquest/** `Campaign` (galaxy of 12 worlds + hyperlanes, owners, fleets, credits, bonuses, class unlocks, AI turns, auto-resolve, JSON save `conquest.json`), `GalaxyView` (3D map).
- **UI/** IMGUI in a virtual 1080-high space: `UI` (helpers), `HUD` (battle HUD, radar, spawn screen, map, scoreboard, pause, results), `MenuUI` (+ partial `ConquestUI`).

## Rules of thumb
- Layers by number only: 8 Ground, 9 Unit, 10 Vehicle, 11 Hull (`Layers`). Friendly fire is off; damage goes through `Shots.Deal` (applies `vsVehicle`, bonuses, hit markers).
- Capital ship local frame: bow +x, hangar opens on +z toward the enemy, hangar floor at y = 0. Interior nav nodes in `CapitalShip.nodes` / `links`.
- Bots set one-shot inputs (swap/equip/ability/jump) and `Unit.Tick` clears them.
- New content = add to `Factions` / `Maps` / `Galaxy.Planets`; models follow `FactionDef.body`.
- Map layouts are `MapFeature`s in the same -1..1 space as posts (x0.72 of the half size = 230 m on the 640 m maps). Ridge / river widths and heights are metres; area radii (forest, town, boulders, lake, crater, ford) are in map units. A road that crosses a ridge or crater rim cuts a pass; one that crosses a river / lava / gulch gets a bridge automatically. Keep features ~35 m+ from post centres (posts flatten a 34 m circle). Check a change with `BattleTest.MapShot(map)`.
- Anything that stands or drives uses `Battle.GroundY` (= `LandWorld.Top`, which includes bridge decks), never `Height` alone. `LandWorld.LiquidAt` tells water (wading x0.55, deep x0.35) from lava (damage).

- **Wi-Fi multiplayer for two (2026-11-06, user: "make this game multiplayer over wifi, so i can put it on my wife's phone and we play together"):** `Net/` (namespace `BIS.Net`). `NetLink` = one TCP connection (port 47777) with length-prefixed messages (`Msg` enum, writer `W` / reader `R`, reader + writer threads), `Discovery` = UDP broadcast on 47778 once a second (Android takes a multicast lock), `Session` = role (None / Host / Client), lobby, `Shutdown`. Menu: PLAY ON WI-FI (`MenuUI.Multi.cs`): HOST A GAME opens the Quickplay screen with a WI-FI GAME panel (TOGETHER = guest on your side, AGAINST = the other side; shows your address; START only once someone has joined); JOIN A GAME lists games heard on the network or takes an address (keypad for phones). After a battle both go back to the lobby still connected; a new Start while the guest is on the results screen moves it straight into the next battle. **Model:** the host runs the battle exactly as single player with one extra human `Participant.remote` (`Participant.Human` = isPlayer or remote; on the guest the host is the `remote` one), bots fill the rest. The guest (`NetClient`) builds the same map (maps are seeded) and the same people list in the host's order (so `Commander` squads match), and draws copies: `Unit.NetMode` / `Vehicle.net` = `Replica` (smoothed to 20 Hz snapshots, a little ahead by velocity), `GuestLocal` = the guest's own soldier and the vehicle it drives, which **move on the guest's device** (no input lag) and send their pose 60 times a second; on the host those are `HostRemote` (`Unit.NetFollow`, `Vehicle.NetPose`: pose from the guest, weapons / abilities / crushing / damage run on the host). Shots: `Shots.Fire` reports every shot (`NetHost.OnShot`), the guest draws it with `Shots.FireVisual` (`Shot.fake`: sparks / explosions, no damage). Damage, scoring, posts, tickets and the rules are host only (`Shots.Deal` and `Crush` do nothing on a client); the guest's own crashes / lava / falls are sent as `SelfDmg`. Guest requests: spawn, enter, exit, seat, hero (checked with the player's rules in `NetHost.Spawn`; refusals come back as `Say`). Events: unit / vehicle spawn and death, kill feed, explosions (`Fx.Explosion` / `Burst` report unless `Fx.netMute`), hit markers, hurt, points, awards, messages from the guest's side (`NetHost.Text`), warp out of a vehicle, knock-back, end. Per-guest `LocalState` 10 Hz (health, weapons, cooldown, locks, points, hero); `Stats` 1 Hz for the scoreboard. Pause doesn't stop time in a Wi-Fi game (you stand still). If the guest leaves, a bot takes their place. Bandwidth ~20 KB/s host to guest. Not sent: mines, detpacks, supply crates and pickups (the guest doesn't see them), melee / blade sounds. **Self-test:** `-nethost [-space] [-against]` and `-netjoin <ip | auto>` (`Core/NetTest.cs`, logs `autotest_net_host.txt` / `autotest_net_guest.txt` in persistentDataPath): two Windows copies on one PC - discovery by broadcast, guest spawned, walked and shot (host's copy within 0.5 m), drove a hover tank 65 m (host within 0.4 m), got out, died and respawned; space: launched, flew 259 m (host 7 m behind at speed), died, respawned in a new fighter; no errors either side. Android has `forceInternetPermission`. Not checked: two phones on real Wi-Fi.
